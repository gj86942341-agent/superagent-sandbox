# 大乐透研究与记录系统

本地、只读、不代购。**它不预测中奖号码**，只做三件事：记录开奖数据、按一套"研究偏好"生成每期 3 注、开奖后对奖并统计。

> "大咖/专家分析"的调研结论见 [`research/lottery-experts.md`](../research/lottery-experts.md)：用本地 2943 期官方数据逐号核验过——**没有任何可验证的稳定优势**，所谓"大底全中"是集合覆盖（5 位专家 20 码并集 34 码，纯随机覆盖 85.71%）。复式的成本与概率见本文「复式投注」一节。

## 一句话事实（写死在系统里，不随"感觉"改变）

前区 35 选 5、后区 12 选 2，每期独立等概率。任意一注中一等奖 **1/21,425,712**，中任意奖约 **6.67%**，长期返奖率约 **51%**（即每 2 元平均亏约 1 元）。
**没有任何生成策略能改变中奖概率**——如果存在，就等于预测了独立随机事件。系统的"优化"只是调整偏好参数、控制预算、降低中奖后被分奖的概率。

## 默认方案：每期一注确定性复式（无随机）

用户要求"每期一注、复式、带追加、不要随机"，所以默认走 `deterministic(6+2+追加)`：

| 项 | 值 |
|---|---|
| 号码池 | 前区 **6** 个 + 后区 **2** 个 |
| 拆成单注 | C(6,5) × C(2,2) = **6 注** |
| 单价 | 基本 2 元 + 追加 1 元 = **3 元/注** |
| 每期成本 | **18 元**（不追加则 12 元）|
| 是否随机 | **否**。同样的数据永远得到同样的号码 |

### 选号规则（确定性，可逐项复核）

```
分数 = 0.55 × 热度 + 0.45 × 回补
热度 = 该号近 30 期出现次数 / 最多次数
回补 = 该号距上次开出的期数 / 最长间隔
若该号出现在上一期 → 分数 × 0.6（避免与上期重号）
```

- 前区按三个区间配额（6 个 → 2/2/2）按分数降序取，同分按号码升序；
- 额外一条确定性去连号规则：优先挑与已选号码不相邻的号；
- 后区取 **分数最高 1 个 + 分数最低 1 个**（一热一冷）。

> **必须清楚**：这两个因子只是对历史的描述，分数高**不代表更容易开出**。它唯一的优点是
> 可复现、可审计、没有随机。想调策略就改 `lottery.py` 里的 `SCORE_WEIGHTS`。

### 切换方式

```cmd
lottery.py predict                    :: 默认：6+2 追加，18 元
lottery.py predict --no-add           :: 6+2 不追加，12 元（正好 12 元）
lottery.py predict --compound 7+2     :: 换 7+2（21 注，追加 = 63 元）
lottery.py predict --compound 6+3     :: 换 6+3（18 注，追加 = 54 元）
lottery.py predict --front 8 --back 2 :: 用 --front/--back 指定池大小
lottery.py predict --singles          :: 回到旧的 3 注单式（对照组，各 2 元）
```

> 为什么"12 元 + 追加"做不到：追加后每注 3 元，12 元只能买 4 注，而复式的注数只能是
> C(前区,5)×C(后区,2)（6、18、21、56…），凑不出 4。所以 12 元对应的是"6+2 不追加"。

## 可选：3 注单式（对照组，用于自证"偏好无效"）

| 注号 | 策略 | 说明 |
|---|---|---|
| 第 1 注 | `uniform` | **纯随机，不加任何滤网** —— 对照组，用来检验"偏好策略是否真的更好" |
| 第 2 注 | `balanced` | 结构均衡偏好：和值 75–115、奇偶 2:3/3:2、大小 2:3/3:2、三区间各≥1、后区一奇一偶 |
| 第 3 注 | `hot-cold` | 近 30 期出现次数：3 热 + 2 冷 |

第 2、3 注共用硬约束：不与上期重号、不含三连号、三区间各≥1、注间前区重叠≤1。
这些滤网**只改变"买哪一注"**；对照组的存在就是为了在数据上证明：过滤后的号码并不比纯随机更容易中。
用 `predict --singles` 生成，成本 **3 注 × 2 元 = 6 元/期**（未开追加）。

## 数据来源

中国体彩网官方历史开奖接口 `webapi.sporttery.cn/gateway/lottery/getHistoryPageListV1.qry`（`gameNo=85`）。
反爬要求：请求必须同时带 `Referer: https://www.sporttery.cn/` 和浏览器型 `User-Agent`，缺一返回 HTTP 567。
奖金金额一律取官方当期 `prizeLevelList` 实发值，不自行按奖池推算。

## 规律研究（诚实版）

报告 `research/lottery-report.md` 用 2943 期数据验证过：冷热号、遗漏、和值、奇偶、区间、连号、重号、跨度、012 路等常见套路**全部没有预测力**；"热号优势"只在 2007–2013 数据段出现，样本外归零。所谓"专家命中率"靠选择性展示与多注覆盖。

因此本系统只做三件诚实的事：
1. **固定成本**：每期 6 元，可设月度预算上限。
2. **避开大众组合**：不提高中奖率，只在万一中浮动奖时降低被平分。
3. **用统计检验说话**：累计命中与理论期望（前区 0.714/注、后区 0.333/注、中奖 6.67%/注）对比，落在随机波动范围内就如实说"是运气"。

## 规则爬虫与漂移检测（`crawler.py`）

对奖规则（7 奖级、开奖时间、价格）是硬编码在 `lottery.py` 里的。官方历史上**改过两次**规则（2007 六奖级 → 九奖级 → 2026-02 七奖级），如果改了而系统没跟上，对奖会静默出错。爬虫就是用来发现这件事的。

### 两个模式

```cmd
%PY% D:\deepseek_space\lottery\crawler.py rules      :: 抓官方规则页并和内置常量比对
%PY% D:\deepseek_space\lottery\crawler.py methods    :: 抓选号方法的公开说明，整理成知识库
%PY% D:\deepseek_space\lottery\crawler.py all
%PY% D:\deepseek_space\lottery\crawler.py rules --offline   :: 用上次缓存重跑解析
```

### 抓谁

| 来源 | 负责的字段 |
|---|---|
| 浙江体彩·大乐透规则全文 `zjtycp.cn/guize_cjdlt/` | 号码范围/个数、开奖日、价格、7 奖级 |
| 河南体彩·时间调整公告 `hnlottery.com.cn/2023/02-22/13561.html` | 停售 21:00、开奖 21:25 |
| 中国体彩网·旧版规则 `sporttery.cn/help/2858.html` | 仅历史留档，**不参与比对**（那是九奖级） |

### 比对结果（2026-11-03 实测）

11 项全部 `ok`，结论 `consistent`。仓库里留了原始页面 `raw/*.html` 与结构化结果 `rules.json`，可复核。

**爬虫立刻纠正过一个真实理解偏差**：官方原文是「每注基本投注金额人民币 **2 元**」「每注追加投注金额人民币 **1 元**」，即追加票总价 3 元。而调研报告里写成"基本 2 元、追加 3 元"，把"追加总价"当成了"追加加价"。代码里因此明确拆成 `PRICE_BASIC=2` / `ADDON_PRICE=1` / `PRICE_ADD=3`。

### 设计要点

1. **单一真相**：`EXPECTED` 直接 import `lottery.py` 的常量，不在爬虫里写第二份；改规则时两边自动同步，比对才有意义。
2. **分来源授权字段**：规则页里也会出现"直播时间 15:55"这类干扰，所以每个来源只允许贡献它负责的字段，时间只认公告页。
3. **抽不到就说未知**：字段解析失败记为 `unknown` 而不是猜一个值；只有真的不一致才 `MISMATCH`。
4. **抓取克制**：一次最多三个页面、请求间隔 1.5 秒、带正常 UA/Referer，不扫站、不高频轮询。

### 自动化

| 通道 | 时间 | 内容 |
|---|---|---|
| Windows 任务 `Lottery Rules Watch` | 每周一 09:00 | 抓规则 → 比对 → 追加到 `rules-watch.log` |
| 看板「大乐透预测记录」卡片 | 实时 | 显示最近一次校验结论与项数 |

## 复式投注（compound）

复式 = 前区选多于 5 个、或后区选多于 2 个，按组合拆成多注单式。**它线性放大成本与覆盖，不改变每注的中奖概率**：每注仍是 1/21,425,712，期望返奖率仍是约 51%。复式真实的作用是"覆盖更多组合、更容易中小奖、也更贵"。

### 命令

```cmd
%PY% lottery.py plans                      :: 常见复式的注数/成本表
%PY% lottery.py predict --compound 7+2     :: 为下一期生成一注复式（与单式并存）
%PY% lottery.py predict --compound 6+3
```

复式选号用的是彩民圈那套话术，实现上只是偏好：**定胆**（近 30 期最热的 2 个前区号直接进池）、**杀号**（全局最冷 2 个排除）、**分区均衡**（三个区间各分到号）、后区一热一冷。

### 成本/覆盖表（2 元/注）

| 方案 | 注数 | 金额 | 中一等奖概率 | 每期都买一年的成本（156 期）|
|---|---|---|---|---|
| 6+2 | 6 | 12 元 | 1 / 3,570,952 | 1,872 元 |
| 6+3 | 18 | 36 元 | 1 / 1,190,317 | 5,616 元 |
| **7+2** | **21** | **42 元** | 1 / 1,020,272 | 6,552 元 |
| 7+3 | 63 | 126 元 | 1 / 340,091 | 19,656 元 |
| 8+2 | 56 | 112 元 | 1 / 382,602 | 17,472 元 |
| 8+3 | 168 | 336 元 | 1 / 127,534 | 52,416 元 |

> 建议"试试"的规模：**7+2（42 元）或 6+3（36 元）**。再往上成本涨得比覆盖快，而且中奖期望永远是负的（约 -49%）。**一定要设月度预算上限。**

### 对奖怎么算

复式票不是"一注更大的票"，而是 N 注单式的组合。对奖时程序把号码池展开成每一注，**逐注判奖后求和**，并记录各奖级各中几注：

```
第 26125 期：7+3 复式（前区含全部 5 个中奖号、后区含全部 2 个）
→ 一等奖 1 注、二等奖 2 注、三等奖 10 注、四等奖 20 注、五等奖 10 注、六等奖 20 注
→ 合计 7,911,293 元（63 注 × 2 元 = 126 元成本）
```

这段是拿真实开奖数据跑出来的，并且和**独立重算**逐项比对一致（`test_compound_flow.py`）。

## 自动成长与优化：有什么、没有什么

### 自动化的部分（不需要人管）

| 做什么 | 频率 | 落在哪 |
|---|---|---|
| 抓开奖数据（增量） | 每天 14:00、21:40 | `lottery.sqlite`（2943 期）|
| 对奖 + 累计 ROI | 每天 14:00、21:40 | `results` 表、`daily.log` |
| 出下一期的一注（确定性复式） | 开奖日 | `tickets` 表 |
| 规则漂移检测 | 每周一 09:00 | `rules.json`、`rules-watch.log` |
| 参数评估月报（walk-forward + 显著性 + 样本外） | 每月 1 日 10:00 | `optimize-report.json`、`optimize.log` |
| 汇总展示 | 实时 | 看板 127.0.0.1:3090 |

### 故意没有的部分：自动"变得更准"

**没有**。这不是偷懒，是数学上不存在可学的信号：每期独立等概率，历史频率不携带关于下一期的信息。
如果让它"按最近表现自动切换参数"，得到的是**过拟合**，不是成长。

`optimize.py` 用 2743 期 walk-forward 回测把这件事量化了（2026-11-03 实测）：

| 窗口 | 热度权重 | 前区均中 | z（按期为聚类）|
|---|---|---|---|
| 20 | 0.3 | 0.7006 | −1.10 |
| 20 | 0.55 | 0.7018 | −1.00 |
| 20 | 0.7 | 0.7030 | −0.90 |
| 30 | 0.3 | 0.7009 | −1.07 |
| 30 | 0.55 | 0.7012 | −1.05 |
| **30** | **0.7** | **0.7142** | **−0.00** |
| 50 | 0.3 | 0.7039 | −0.83 |
| 50 | 0.55 | 0.7288 | 1.12 |
| 50 | 0.7 | 0.7227 | 0.66 |

理论随机值 **0.7143**。9 个组合全部落在随机波动内；按 Bonferroni 校正（阈值 |z|>2.87）**无一显著**。

更关键的是**样本外验证**：用前 70% 数据挑出的"冠军"（窗口 50、热度 0.55）在样本内均中 **0.7457**，
到后 30% 只剩 **0.6896**（z=−1.05）——**领先消失，甚至低于随机**。这就是"自动调参"会踩的坑。

### 那"成长"体现在哪

1. **数据资产**：2943 期官方开奖 + 各奖级实发奖金，逐期可查。
2. **规则感知**：官方改规则（如 2026-02 由九奖级改七奖级）能自动发现，而不是静默算错。
3. **成本与预算纪律**：固定 18 元/期、可查累计投入与 ROI、月预算上限。
4. **可审计**：每一期号码都能用同样的规则重算出来，评分逐项可复核。
5. **反脆弱**：先证明"没有策略有效"，再据此控制投入——这比相信"能变强"更值钱。

```cmd
%PY% optimize.py            :: 跑完整评估（约 10 秒），输出表格 + 样本外结论
%PY% optimize.py --quick    :: 只跑 3 个组合
```
